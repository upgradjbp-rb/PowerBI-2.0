    Topic 1: Data Ingestion 00:30 – 00:36

    Topic 1: Connecting Data — CSV vs. Folder Connector

    How do we bring JioWave's files into Power BI Desktop so that next month's refresh takes 1 click instead of 2 hours?

    Method A: Text/CSV Connector (Single File)

    Use Case: Loading one standalone file like subscribers.csv or plans.csv.

    Home → Get Data → Text/CSV → Select File → Transform Data

    Limitation: If you have 12 monthly billing CSVs (Jan.csv, Feb.csv...), importing them one by one creates 12 separate tables!

    Method B: Folder Connector (Enterprise Best Practice)

    Use Case: Pointing Power BI to an entire folder (e.g., JioWave_CSV_Files/). Power BI reads every file inside and lets you either load them individually or combine monthly dumps automatically.

    Home → Get Data → More → Folder → Browse Folder → Transform Data

    Advantage: Next quarter, drop new files into the folder and click Refresh!

    Topic 2: Power Query Architecture 00:36 – 00:42

    Topic 2: How Power Query Works (The Non-Destructive Recipe)

    Why Power Query destroys manual Excel cleaning for recurring monthly reporting.

    Commerce Analogy: Recording a Macro vs. Manual Erasing

    In Excel, if you delete a duplicate row and press Save, the original data is gone—and next month you must repeat all 20 clicks manually. Power Query never modifies your original CSV file. Instead, it records every click in a right-hand list called Applied Steps (written in M language). Next month, Power Query replays your recipe in 2 seconds!

    1. Ribbon (4 Main Tabs)
    • Home: Remove rows/columns, split, group, merge.
    • Transform: Modify the existing column in-place.
    • Add Column: Create a brand new column from existing ones.
    • View: Turn on Column Quality & Distribution bars!
    2. Formula Bar (M Language)

    Case-sensitive functional language! Table.Distinct works; table.distinct throws an error. Always inspect the formula bar to learn the syntax.

    3. Applied Steps (Right Pane)

    Every transformation is a step. Click any previous step to "time-travel" and inspect what the table looked like at that exact stage.

    Topic 4: Row Deduplication 00:48 – 00:54

    Topic 4: Removing Duplicate Rows (`Table.Distinct`)

    If a subscriber appears twice in our master dimension table, we will double-count their revenue and distort churn!

    Syntax & Variations
    // Variation 1: Remove exact row duplicates across ALL columns
    Table.Distinct(PreviousStep)

    // Variation 2: Deduplicate based on Primary Key column ONLY
    Table.Distinct(PreviousStep, {"subscriber_id"})

    UI Path: Select subscriber_id column → Home → Remove Rows → Remove Duplicates.

    Critical Power Query Trap: Case Sensitivity!

    In Power Query, "sub001" and "SUB001" are treated as different values! Always run Transform → Format → UPPERCASE on ID columns before clicking Remove Duplicates.

    JioWave Impact: Removes 200 duplicate rows, bringing subscribers from 28,200 down to exactly 28,000.

    Topic 5: Text Hygiene 00:54 – 01:00

    Topic 5: Fixing Dirty Text (`Text.Proper`, `Text.Trim`, `Text.Clean`)

    Why does JioWave appear to operate in 96 cities instead of 32? Because regional CRM portals typed city names inconsistently.

    1. `Text.Trim` (Spaces)

    Removes leading and trailing spaces (e.g., " Mumbai " → "Mumbai"). Does not remove spaces between words like "New Delhi".

    2. `Text.Clean` (Hidden Chars)

    Strips invisible line breaks (Alt+Enter) and tab characters copied from PDFs or web forms.

    3. `Text.Proper` (Title Case)

    Capitalizes the first letter of every word: "MUMBAI" and "mumbai" both become "Mumbai".

    // M-Code generated via Transform → Format → Capitalize Each Word on `subscribers.csv`:
    ProperCity = Table.TransformColumns(DeduplicatedRows, {{"city", Text.Proper, type text}})

    Topic 6: NULL Strategy 01:00 – 01:06

    Topic 6: Smart NULL Handling — Don't Blindly Delete Rows!

    In `subscribers.csv`, 848 rows have `city = null`, yet every single one of those 848 rows has a valid `home_tower_id`!

    Auditor's Rule: Never Throw Away a Voucher Because One Field Is Blank

    If a customer invoice has a blank "City" field, do you tear up the invoice and lose ₹10,000 of recorded revenue? No! You look up the branch code on the invoice to find the city. Similarly, every JioWave subscriber has a home_tower_id (like TW0081), and towers.csv knows that TW0081 is in Mumbai!

    1. `Table.ReplaceValue`

    Best when NULL has a known default label. Used on full_name (844 nulls → "Unknown Subscriber") and occupation (622 nulls → "Not Disclosed").

    2. `Table.FillDown` / `FillUp`

    Used when exported Excel reports leave blank cells below a group header. Never use FillDown on subscriber tables (it copies the previous customer's city onto the next customer!).

    3. Relational Lookup (`Merge`)

    The gold-standard fix for JioWave's 848 NULL cities: match subscribers[home_tower_id] with towers[tower_id] to recover the exact city!

    // Syntax for replacing NULL text values in `subscribers.csv`:
    Table.ReplaceValue(PrevStep, null, "Unknown Subscriber", Replacer.ReplaceValue, {"full_name"})
    Topic 7: Data Types 01:06 – 01:12

    Topic 7: Data Types — Why "1,062" Breaks Math

    Power BI stores numbers, dates, and text differently. Wrong data types prevent SUM/AVERAGE calculations and break date filters.

    Common Type Traps in JioWave
    • tenure_days in `subscribers.csv`: Contains commas ("1,062"). Stored as Text (ABC). Must convert to Whole Number (123).
    • rental_inr in `revenue_monthly.csv`: Has paise decimals (309.58). Use Decimal Number (1.2) or Fixed Decimal Currency ($).
    • signup_date & churn_date: Stored as YYYY-MM-DD. Convert to Date (not Date/Time, which wastes memory).
    • billing_cycle_day & age: Always Whole Number.
    Using Locale (`Change Type → Using Locale`)

    When CSV dates arrive in Indian/UK format (DD-MM-YYYY like 25-02-2025) on a US-configured laptop, standard Date conversion throws an Error on day 25!

    Table.TransformColumnTypes(Source, {{"signup_date", type date}}, "en-IN")

    Always specify "en-IN" (English - India) when parsing regional dates and comma-formatted numbers!

    Topic 10: Text Parsing 01:24 – 01:30

    Topic 10: Splitting & Extracting Strings (`Text.BeforeDelimiter`)

    Look at `occupation` in `subscribers.csv`: values are stored as `"Salaried-IT"` and `"Salaried-NonIT"`. How do we separate employment type from sector?

    Split Column by Delimiter (`-`)

    Splits one column into two columns at the hyphen "-".

    Transform / Add Column → Split Column → By Delimiter → Custom ("-")
    Table.SplitColumn(PrevStep, "occupation",
      Splitter.SplitTextByDelimiter("-", QuoteStyle.Csv),
      {"Employment_Type", "Sector"})
    Extract Text Before Delimiter

    Extracts only the prefix without creating extra columns—great for pulling "JioPost" from "JioPost 699" in plans.csv!

    Table.AddColumn(Plans, "Plan_Family",
      each Text.BeforeDelimiter([plan_name], " "))

    Topic 12: Vertical Stacking 01:36 – 01:40

    Topic 12: `Table.Combine` (Append Queries = Stacking Ledgers)

    Understand the difference between Merge (adding columns sideways) and Append (stacking rows vertically).

    Commerce Analogy: Adding Columns vs. Stapling Pages

    Merge is like looking up a customer's address from an address book and writing it in a new column on the right. Append is like taking April's sales register, May's sales register, and June's sales register (all having the exact same column headers) and stapling them together into one Q1 Sales table.

    // M-Syntax when stacking regional or monthly extracts:
    CombinedRevenue = Table.Combine({Revenue_FY24, Revenue_FY25, Revenue_FY26})

    Golden Rule of Append: Column names must match exactly (including spelling and case). If one table calls it Revenue and another calls it revenue_inr, Power Query creates two separate columns with NULLs!

    Topic 15: Best Practices 01:49 – 01:52

    Topic 15: Power Query Hygiene & Performance Best Practices

    Five habits that separate a ₹15 LPA Data Analyst from a spreadsheet hobbyist.

    1. Rename Your Applied Steps!

    Instead of leaving Changed Type1, Replaced Value2, right-click and rename steps to 01_Removed_Duplicate_Subs, 02_Standardized_City_Case. Your future self (and your interviewer) will thank you.

    2. Filter Early, Sort Late (or Never)

    Always filter out unnecessary rows at the top of Applied Steps. Never sort tables inside Power Query—sorting 564,274 rows slows refresh speed and gets overridden by visuals anyway.

    3. Disable Load on Staging Queries

    If you import a helper table only to Merge it into another table, right-click the helper query and uncheck Enable Load so it doesn't bloat your Power BI data model.

    4. Document Your Data Quality Log

    Remember the JioWave Grading Rubric (10% weight): every assumption (like rescuing NULL cities via home_tower_id) must be documented in JioWave_Build_Notes.md.
