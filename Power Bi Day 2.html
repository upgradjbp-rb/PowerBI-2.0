    Topic 1: Date Engineering 00:06 – 00:12

    Topic 1: Power Query Date Functions (`Date.Year`, `Date.QuarterOfYear`)

    Remember CMO Rashmi's #1 question? "Find the vintage cohort churning at 61%!" Vintage cohort simply means the Quarter a customer joined.

    Step 1: Parse Mixed Dates Safely
    Right-Click `signup_date` → Change Type → Using Locale → Date → English (United Kingdom)
    Table.TransformColumnTypes(PrevStep, {{"signup_date", type date}}, "en-GB")

    Setting locale to "en-GB" or "en-IN" handles both 29/07/2025 and 2025-11-06 cleanly!

    Step 2: Build `Vintage_Cohort` Column (`2024Q3`)
    Add Column → Custom Column
    Text.From(Date.Year([signup_date])) & "Q" & Text.From(Date.QuarterOfYear([signup_date]))

    Output: 2024-08-14 becomes "2024Q3"—the exact key needed to uncover the PL015 churn disaster!

    Topic 6: Enterprise Architecture 00:36 – 00:42

    Topic 6: Query Folding — Why Order of Steps Matters

    Remember the JioWave case brief mentions `JioWave_Database.sqlite` and `JioWave_MySQL_Dump.sql`? In enterprise roles, Power BI connects directly to SQL databases.

    What is Query Folding?

    Query Folding is Power Query's ability to translate your clicks (Filter, Group By, Remove Columns) into one single SQL query executed by the fast database server—instead of downloading 10 million rows to your laptop first!

    How to Check & Preserve Folding
    • Right-click any Applied Step → if "View Native Query" is clickable (not greyed out), folding is active!
    • Golden Rule: Always put Filter Rows and Remove Columns before complex text formulas or custom functions.
    Topic 7: Automation 00:42 – 00:48

    Topic 7: Writing Your First Custom M Function (`fnCleanText`)

    Instead of clicking Trim → Clean → Proper on 6 columns across 3 tables, write one reusable function!

    // In Home → New Source → Blank Query → Advanced Editor, name it `fnCleanText`:
    (rawText as nullable text) as nullable text =>
    let
      Trimmed = Text.Trim(rawText),
      Cleaned = Text.Clean(Trimmed),
      ProperCased = Text.Proper(Cleaned)
    in
      ProperCased

    Invoke Custom Function: Go to Add Column → Invoke Custom Function and apply fnCleanText to any dirty text column in 2 clicks!

    Module 2: Data Modeling 00:54 – 01:02

    Module 2: Why Not Merge All 9 CSVs into One Giant Excel Sheet?

    Every Excel user's first instinct is to VLOOKUP everything into one flat 564,274-row table. Here is why that destroys Power BI.

    The "Flat Table" Disaster
    • Memory Explosion: Repeating a customer's full_name, city, state, occupation, and plan_name 36 times across 564,274 billing rows bloats file size 10×.
    • Double-Counting Trap: If a subscriber switched plans in subscriptions.csv (2 rows for 1 customer) and you join it to revenue_monthly.csv, their revenue gets doubled!
    • Slow Refresh: Recalculating one massive flat table takes minutes instead of milliseconds.
    The Power BI Solution: Star Schema

    Instead of merging everything into one bloated sheet, we load clean, separate tables into Model View and connect them via lightweight Relationships.

    Analogy: Master Registers vs. Daily Transaction Books

    Keep your Customer Master (28,000 rows) separate from your Monthly Billing Register (564,274 rows), linked only by subscriber_id!

    Topic 9: Star Schema Core 01:02 – 01:10

    Topic 9: Fact Tables vs. Dimension Tables (WHO vs. HOW MUCH)

    Every single table in our JioWave warehouse falls into one of two clear buckets.

    Dimension Tables (`dim_`) = WHO, WHAT, WHERE

    Describe business entities. They are short & wide (many descriptive attributes, few rows, unique Primary Key).

    • dim_subscribers (28,000 rows): Name, Tier, City, Vintage Quarter.
    • dim_plans (24 rows): Plan Name, Rental, Data Quota.
    • dim_towers (279 rows): Tower Name, City Tier, 4G/5G, Capex Cycle.
    • dim_date (1,096 rows): Fiscal Year, Quarter, Month (we will build this!).
    Fact Tables (`fact_`) = HOW MUCH, WHEN

    Record measurable business events and numbers. They are tall & narrow (hundreds of thousands of rows, numeric metrics + Foreign Keys).

    • fact_revenue_monthly (564,274 rows): Rental, Overage, Add-on INR.
    • fact_usage_monthly (564,274 rows): Data GB, Voice Minutes, SMS.
    • fact_tower_metrics (10,044 rows): Traffic GB, Utilization %, Downtime.
    • fact_subscriptions (32,728 rows) & fact_migrations (4,728 rows).

    Topic 11: Relationship Rules 01:18 – 01:25

    Topic 11: Primary Keys, Foreign Keys & Cardinality (`1 : *`)

    Before dragging a relationship line between two tables, check two rules: Unique Keys and Cardinality.

    1. One-to-Many (`1 : *`) — GOLD STANDARD

    dim_subscribers[subscriber_id] has 1 unique row per customer. fact_revenue_monthly[subscriber_id] has many (*) monthly bills per customer. Always aim for 1 : *!

    2. One-to-One (`1 : 1`) — RARE

    Both tables have unique keys. Usually means the two tables should simply be merged into one Dimension table in Power Query.

    3. Many-to-Many (`* : *`) — DANGER!

    Happens if you forget to remove the 200 duplicate rows in subscribers.csv! Power BI refuses 1 : * and warns of ambiguous totals.

    Topic 12: Filter Propagation 01:25 – 01:32

    Topic 12: Cross-Filter Direction — Why "Single" Beats "Both"

    Think of relationship arrows as one-way traffic valves controlling how slicer clicks flow across your dashboard.

    Single Direction (`dim` ➔ `fact`) — ALWAYS DEFAULT

    When Rashmi clicks City = "Mumbai" in a slicer from dim_subscribers, the filter arrow travels downhill into fact_revenue_monthly and sums only Mumbai revenue.

    Safe & Fast: Prevents circular loop errors when multiple fact tables exist.

    Bi-Directional (`dim` ⇄ `fact`) — AVOID!

    Allows filters to travel uphill from Fact to Dimension. If you turn on Bi-Directional filtering across fact_revenue and fact_usage, Power BI blocks the relationship due to ambiguity (two competing filter paths!).

    Topic 13: Multi-Date Modeling 01:32 – 01:38

    Topic 13: Active vs. Inactive Relationships (Solid vs. Dotted Lines)

    Look at `dim_subscribers`: each row has TWO dates—`signup_date` AND `churn_date`! How do we connect both to our Calendar table?

    The Power BI Rule: Only ONE Active Path

    Between any two tables, Power BI allows only one solid (Active) relationship line at a time. Any second relationship appears as a dotted (Inactive) line.

    • Active (Solid): dim_date[Date] ➔ dim_subscribers[signup_date] (Counts New Acquisitions).
    • Inactive (Dotted): dim_date[Date] ┄➔ dim_subscribers[churn_date] (Activated inside DAX via USERELATIONSHIP() when counting Monthly Churned Users!).
    Why Not Create Two Separate Date Tables?

    If you create two Date tables, the CMO has to click two different "Month" slicers on the dashboard! Keeping one master Date table with one active and one inactive line lets a single Month slicer control both Acquisitions and Churns.

    Topic 14: Time Intelligence Foundation 01:38 – 01:45

    Topic 14: Building a Dedicated `dim_date` Table (Indian Fiscal Year!)

    JioWave operates on the Indian Fiscal Year (April 1 to March 31: FY24, FY25, FY26). Power BI's built-in Auto Date/Time only understands Jan–Dec!

    // Modeling Tab → New Table → Paste this DAX Calendar script:
    dim_date =
    ADDCOLUMNS(
      CALENDAR(DATE(2023, 4, 1), DATE(2026, 3, 31)),
      "Calendar_Year", YEAR([Date]),
      "Month_Num", MONTH([Date]),
      "Month_Name", FORMAT([Date], "MMM"),
      "Fiscal_Year", IF(MONTH([Date]) >= 4, "FY" & RIGHT(YEAR([Date]) + 1, 2), "FY" & RIGHT(YEAR([Date]), 2)),
      "Fiscal_Quarter", "FQ" & ROUNDUP(MOD(MONTH([Date]) - 4, 12) + 1, 0) / 3
    )
    Mandatory Step: Table Tools → Mark as Date Table → Select `[Date]` Column!

    Troubleshooting Guide 01:59

    5 Data Modeling Bugs That Break Power BI Dashboards

    If a visual shows the exact same repeated number on every row of a table, check this list immediately!

    Symptom 1: Every Bar in a Chart Shows the Same Total

    Cause: Missing relationship between the Dimension table on your chart axis and the Fact table in your Values field! Connect them in Model View.

    Symptom 2: "Can't create relationship because duplicate values exist"

    Cause: Trailing spaces or case differences in your Dimension key (e.g., "TW001" vs "tw001"). Run Text.Upper + Text.Trim + Table.Distinct in Power Query.

    Symptom 3: Date Slicer Doesn't Filter Revenue

    Cause: You dragged fact_revenue_monthly[revenue_month] into the slicer instead of dim_date[Date], or forgot to link dim_date to the fact table.

    Symptom 4: Auto Date/Time Bloating `.pbix` Size

    Cause: Power BI secretly creates hidden calendar tables for every date column. Turn it off via File → Options → Data Load → Uncheck Auto date/time once your custom dim_date is marked!
