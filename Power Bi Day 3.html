    Topic 1: Core Architecture 00:06 – 00:13

    Topic 1: Calculated Columns vs. Measures (The #1 Interview Question)

    Look at Principle #3 in the JioWave Case Study Brief: "If it's in a visual, it's a measure. Calculated columns balloon the .pbix and don't respect filter context."

    Calculated Column (Stored in RAM)
    • Computes row-by-row during data refresh and physically saves a new column inside the table.
    • Consumes laptop memory (RAM) on all 564,274 rows of fact_revenue_monthly.
    • Only use when: You want to put the result on a Slicer, Chart Axis, or Table Row (e.g., Age_Group or Vintage_Cohort).
    Measure (Calculated On-the-Fly)
    • Computes an aggregate value dynamically based on whatever filters/slicers the CMO currently selected.
    • Takes 0 bytes of RAM—it is just a saved formula definition!
    • Always use for: KPIs, Ratios, Percentages, Sums, and Averages (Churn %, ARPU, Total Revenue).
    Why Ratios MUST Be Measures, Never Calculated Columns

    Suppose Row 1 has Churn = 10% and Row 2 has Churn = 50%. If you create a Calculated Column for Churn % and drop it into a visual, Power BI averages 10% and 50% to give 30%—even if Row 1 had 10,000 customers and Row 2 had 10 customers! A Measure sums total churned customers first, then divides by total subscribers.

    Topic 3: Aggregation Functions 00:18 – 00:25

    Topic 3: Core Aggregators (`SUM`, `AVERAGE`, `COUNTROWS`, `DISTINCTCOUNT`)

    Let's build our foundational JioWave KPIs and verify their exact values against the dataset.

    // 1. Total Billed Revenue across all 564,274 billing records:
    Total Revenue INR = SUM(fact_revenue_monthly[total_inr]) -- Result: ₹28,26,42,978 (₹28.26 Cr)

    // 2. Total Unique Subscribers in our cleaned Master Dimension:
    Total Subscribers = COUNTROWS(dim_subscribers) -- Result: 28,000

    // 3. Unique Billed Subscribers inside the Fact table:
    Billed Subscribers = DISTINCTCOUNT(fact_revenue_monthly[subscriber_id])
    `COUNT` vs. `COUNTROWS`

    COUNT(dim_subscribers[city]) skips blank/null cells! COUNTROWS(dim_subscribers) counts every row in the table cleanly and runs faster in Power BI's VertiPaq engine.

    Safe Division with `DIVIDE(Num, Denom, Alt)`

    Never write [Churned] / [Total] with a slash /! If a filter yields 0 subscribers, / displays ugly Infinity or NaN. Always use DIVIDE([Churned], [Total], 0).

    Topic 4: The Two Contexts 00:25 – 00:34

    Topic 4: Row Context vs. Filter Context — Mastering the DAX Brain

    90% of DAX confusion disappears once you separate these two concepts.

    1. Row Context ("One Row at a Time")

    Exists automatically inside a Calculated Column or an Iterator function (`SUMX`, `AVERAGEX`).

    Imagine pointing your finger at Row 1 of fact_revenue_monthly and computing rental_inr + overage_inr + addon_inr, then moving your finger to Row 2. Row Context knows "which row I am on," NOT "what the total of the table is."

    2. Filter Context ("The Active Slice of Data")

    Exists automatically inside every Visual & Measure.

    Before SUM(fact_revenue_monthly[total_inr]) calculates anything, Power BI applies all active filters from Slicers, Table Rows, Chart Axes, and Star Schema relationships—shrinking the visible table to only matching rows!

    Topic 6: Row-by-Row Iterators 00:40 – 00:48

    Topic 6: Iterator Functions (`SUMX`, `AVERAGEX`) — Multiplication Without Extra Columns

    Standard `SUM()` only accepts a single column name. What if you want to compute `Rental + Overage` row-by-row inside a Measure?

    // Syntax: SUMX( <Table to Loop Over>, <Expression Evaluated on Each Row> )

    // Example 1: Compute Base + Overage Revenue without creating a Calculated Column:
    Core Billed Revenue = SUMX(fact_revenue_monthly, fact_revenue_monthly[rental_inr] + fact_revenue_monthly[overage_inr])

    // Example 2: Average Monthly Bill per Subscriber using AVERAGEX:
    Avg Monthly Bill = AVERAGEX(fact_revenue_monthly, fact_revenue_monthly[total_inr])

    Topic 7: Context Modification 00:48 – 00:58

    Topic 7: `CALCULATE()` — The Single Most Powerful Function in Power BI

    If you master only one function in DAX, make it `CALCULATE()`. It is the ONLY function capable of changing Filter Context.

    Commerce Analogy: Adding an Overriding Clause to an Audit Query

    Suppose your dashboard page has no filter selected, and you want a dedicated KPI card that always shows Churned Subscribers (where is_churned = 1) or Premium Tier Revenue—regardless of other visuals. CALCULATE() steps in before the math runs, applies your custom filter rules, and then evaluates the expression!

    // Syntax: CALCULATE( <Expression>, <Filter 1>, <Filter 2>, ... )

    // 1. Count Churned Subscribers across JioWave:
    Churned Subscribers = CALCULATE(COUNTROWS(dim_subscribers), dim_subscribers[is_churned] = 1)

    // 2. Annual / Overall Churn Rate %:
    Churn Rate % = DIVIDE([Churned Subscribers], [Total Subscribers], 0)

    // 3. Premium-Tier Revenue (Always locked to Premium segment):
    Premium Tier Revenue = CALCULATE([Total Revenue INR], dim_subscribers[subscriber_tier] = "Premium")
    Topic 8: Percentage of Total 00:58 – 01:08

    Topic 8: `ALL()` & `REMOVEFILTERS()` — Computing "% Share of Total"

    Remember CMO Rashmi's question: "What share of total churned subscribers comes from the worst cohort?" To compute "% of Total," we must divide a filtered slice by the unfiltered grand total!

    // Step 1: Ignore any filter on subscriber_tier to get Grand Total Churned (3,352):
    All Churned Subscribers = CALCULATE([Churned Subscribers], REMOVEFILTERS(dim_subscribers[subscriber_tier]))

    // Step 2: Share of Total Churn %:
    Share of Total Churn % = DIVIDE([Churned Subscribers], [All Churned Subscribers], 0)
    How `REMOVEFILTERS()` Enables "% Share of Total" in a Table Visual
    subscriber_tier [Churned Subscribers] [All Churned Subscribers] (`REMOVEFILTERS`) [Share of Total Churn %]
    Mass 2,685 3,352 2,685 ÷ 3,352 = 80.10%
    Premium 581 3,352 581 ÷ 3,352 = 17.33%
    Diamond 86 3,352 86 ÷ 3,352 = 2.57%
    Topic 9: Subtle DAX Behavior 01:08 – 01:15

    Topic 9: `KEEPFILTERS()` — Avoiding the "Repeated Number" Bug

    What happens if you put `[Premium Tier Revenue]` inside a table broken down by `subscriber_tier`?

    Without `KEEPFILTERS` (Overwrites Row Filter!)
    CALCULATE([Total Revenue INR], dim_subscribers[subscriber_tier] = "Premium")

    Even on the Mass row and Diamond row, it overwrites the row filter and repeats ₹8.53 Cr on every single line!

    With `KEEPFILTERS` (Respects Row Filter!)
    CALCULATE([Total Revenue INR], KEEPFILTERS(dim_subscribers[subscriber_tier] = "Premium"))

    Shows ₹8.53 Cr on the Premium row and Blank on Mass & Diamond rows—clean and intuitive!

    Topic 10: Complex Conditions 01:15 – 01:23

    Topic 10: `FILTER()` — Multi-Column & Measure-Based Conditions

    Simple boolean filters in `CALCULATE` (like `is_churned = 1`) only allow a single column compared to a fixed value. What if we want to compare two columns or filter by a Measure?

    // Example 1: Find billing rows where Overage exceeded 50% of Rental (2 columns compared!):
    High Overage Billing Count =
    CALCULATE(
      COUNTROWS(fact_revenue_monthly),
      FILTER(fact_revenue_monthly, fact_revenue_monthly[overage_inr] > 0.5 * fact_revenue_monthly[rental_inr])
    )

    // Example 2: Count "Data Hog" monthly events (>50 GB consumed):
    Data Hog Events = CALCULATE(COUNTROWS(fact_usage_monthly), fact_usage_monthly[data_consumed_gb] > 50)
    Topic 11: Multi-Date Modeling 01:23 – 01:31

    Topic 11: `USERELATIONSHIP()` — Counting Monthly Churns vs. Acquisitions

    Remember Day 2 Slide 15? Our `dim_date` table has an Active solid line to `signup_date` and an Inactive dotted line to `churn_date`.

    Measure 1: New Acquisitions (Uses Active Line)
    New Acquisitions = COUNTROWS(dim_subscribers)

    When you plot this by dim_date[Month_Name], Power BI automatically uses the solid line on signup_date.

    Measure 2: Monthly Churned Users (Activates Dotted Line!)
    Monthly Churned Users =
    CALCULATE(
      COUNTROWS(dim_subscribers),
      dim_subscribers[is_churned] = 1,
      USERELATIONSHIP(dim_date[Date], dim_subscribers[churn_date])
    )

    Topic 13: Clean & Fast DAX 01:38 – 01:45

    Topic 13: Writing Readable, High-Speed DAX with `VAR ... RETURN`

    Variables let you break complex business formulas into named steps—making them 3× easier to debug and twice as fast to execute!

    // Example: Compute Plan Migration Down-to-Up Pressure Ratio (Target: 3.68x)
    Down to Up Migration Ratio =
    VAR DownCount = CALCULATE(COUNTROWS(fact_plan_migrations), fact_plan_migrations[direction] = "Down")
    VAR UpCount = CALCULATE(COUNTROWS(fact_plan_migrations), fact_plan_migrations[direction] = "Up")
    RETURN
      DIVIDE(DownCount, UpCount, 0)

    Debugging Trick: Temporarily replace the expression after RETURN with DownCount to inspect intermediate step results in a KPI card!

    Topic 14: Advanced DAX Concept 01:45 – 01:51

    Topic 14: Context Transition — Why Calling a Measure Inside `AVERAGEX` Works

    Remember Principle #4 in the JioWave PDF? "CALCULATE() is the workhorse. Understand context transition."

    What Is Context Transition?

    Whenever you call a Measure (like [Total Revenue INR]) inside a row-by-row loop like AVERAGEX(dim_subscribers, [Total Revenue INR]), Power BI silently wraps the measure in CALCULATE()—turning the current subscriber's row into a Filter Context! That means for Subscriber 1, it sums only Subscriber 1's bills; for Subscriber 2, only Subscriber 2's bills, and then averages them all!

    // True Customer Lifetime Revenue per Subscriber (LTV):
    Avg Lifetime Revenue per Sub = AVERAGEX(dim_subscribers, [Total Revenue INR])
