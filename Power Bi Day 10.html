    Topic 1: Data Governance (RLS) 00:08 – 00:18

    Topic 1: Static Row-Level Security (`Modeling → Manage Roles`)

    Because we built a clean Star Schema in Day 2, filtering `dim_subscribers[region]` automatically cascades downhill to filter `fact_revenue_monthly` and `fact_usage_monthly`!

    4-Step Static RLS Setup
    1. Go to Modeling Tab → Security Group → Manage roles.
    2. Click + New and create 5 regional roles: RM_North, RM_South, RM_West, RM_East, RM_Central (plus Executive_All_India with no filter).
    3. Select dim_subscribers and enter the DAX filter expression: [region] = "West".
    4. Click Save, then click View as (Modeling Tab) and check RM_West to watch all 5 pages instantly recalculate for West Zone only!
    DAX Filter Expressions for Each Role
    // Role: RM_West (Applied on dim_subscribers)
    dim_subscribers[region] = "West"

    // Role: RM_South
    dim_subscribers[region] = "South"

    // Role: Executive_CMO (No filter = Full 28,000 base)
    TRUE()

    Topic 2: Dynamic RLS with `USERPRINCIPALNAME()` (Interview Favorite!)

    What if JioWave has 32 City Managers? Creating 32 manual roles is tedious. Instead, use ONE dynamic role tied to the logged-in user's corporate email!

    // Step 1: Maintain a small lookup table `dim_security_access` (Email | Assigned_City)
    // Step 2: Create ONE role called `Dynamic_City_Manager` with this DAX rule:

    dim_security_access[Manager_Email] = USERPRINCIPALNAME()

    How It Works: When priya.sharma@jiowave.in opens the dashboard on her laptop or phone, USERPRINCIPALNAME() detects her email, filters dim_security_access to Pune, and filters the entire Star Schema to Pune automatically!

    Topic 4: Speed & Tuning 00:36 – 00:46

    Topic 4: Performance Analyzer — Making Every Page Load in Under 1 Second

    Before publishing to Power BI Service, run the built-in Performance Analyzer (`View → Performance analyzer`) to catch slow visuals.

    1. Check Visual Load Times

    Click Start recording → Refresh visuals. Inspect DAX query time vs. Visual display time. Any visual taking >1,500 ms needs optimization.

    2. Keep Visuals ≤ 6 per Page

    Every visual sends a separate DAX query to the engine. Six focused visuals load in 400 ms; twenty cluttered visuals crawl.

    3. Turn Off Auto Date/Time

    Verify File → Options → Data Load → Auto date/time is unchecked so hidden date tables don't waste memory.

    Topic 5: Cloud Deployment 00:46 – 00:56

    Topic 5: Publishing to Power BI Service & Scheduling Daily 06:00 AM Refresh

    Power BI Desktop is where you author; Power BI Service (`app.powerbi.com`) is where executives consume and collaborate.

    Deployment & Refresh Pipeline
    1. Click Home Tab → Publish and choose your workspace (e.g., JioWave_Executive_Analytics).
    2. In Power BI Service, open the Semantic Model Settings: configure your On-premises Data Gateway (if reading local CSV folder) or Cloud credentials.
    3. Expand Refresh → Schedule refresh: turn ON, set Frequency = Daily, Time = 06:00 AM IST.
    4. Go to Security on the Semantic Model and assign Zonal RMs to their RLS roles (RM_West, RM_South, etc.).
